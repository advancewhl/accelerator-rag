## 3. 入库检查发现及修复

| 发现 | 修复及验证 |
| --- | --- |
| 建索引脚本把 QdrantClient 当作上下文管理器，实际不支持 | 改为 `contextlib.closing`；通过真实脚本 `--apply` 路径测试，使用本地 Qdrant 与明确标记的测试嵌入器 |
| 空文档被跳过，旧版本可能仍留在索引中 | 在收集阶段报错，构建前要求存在合格块；不擅自删除旧文档 |
| 本地目录存在但集合缺失时可能创建空集合 | 应用路径要求目标集合已存在 |
| 代码围栏以简单开关处理，较短或不同类型围栏会误终止 | 按围栏字符和长度匹配，新增嵌套围栏回归 |
| Markdown 被标为 PDF 页码，并交给 PDF.js | 引用及模型上下文增加位置类型；目录区分 MD；新增章节接口和 Markdown 阅读器 |
| 原文消失后 `/view` 可能抛出文件读取错误 | 返回明确 404，与原文下载和章节接口一致 |
| 旧题校验只验证文件／行号存在 | v2 校验文档修订版、位置类型、原文摘录、合格块和块 ID；失效证据直接失败 |

本轮没有实现自动依赖传播、过期知识隔离或自动双路发布。现有逐篇替换仍不是跨索引事务，删除登记记录也不会自动删除旧向量。这些限制保留在入库手册中。
