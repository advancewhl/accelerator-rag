# 论文素材：证据包检索与组合方法

日期：2026-11-08。对应方案 §4.2、§6、§8 与 §10 阶段三。所有数字来自 `reports/phase3/` 的 dev/val 运行；统计按题聚合，正式论文须按 cluster/文档族聚类并给出置信区间。

## 1. 要解决的问题

现有链路把检索单位固定为父块，最终最多选 5 个父块、6,000 个证据 token。对跨表连接、完整清单和“要求—测试—验收”组合题，这种选择对象有两个结构性问题：

1. **粒度不匹配**：一个父块可能包含整张表或整页扫描，真正的证据只是一行、一个条件或表头；为了一个行记录付出整块 token。
2. **关系不完整**：按主题相关性排序的父块可以“找到相似段落”，却可能缺少对端身份、单位、条件、测试范围或另一版本，导致结论不可复核。

阶段三把选择对象改为：**在 token 预算内覆盖问题必要关系的证据包**。证据包由可定位原子（段落句、表格行、表头、表题、脚注、外部观测）组成；完整父块仍被引用供查阅，但不占证据包预算。

## 2. 形式化

问题解析得到需要 \(N=(E,R)\)：

- 实体需要 \(E\)：机柜、设备、线缆、端口、PV、修订号、数值；`raw` 逐字保留，`normalized` 只用于比较。
- 关系需要 \(R\)：`value/unit/condition/counterpart/scope/enumeration/version_left/version_right/requirement/design/test_result/test_scope/acceptance/boundary/provenance/external_observation`；每项标记 `required`。

证据原子 \(a\) 是五元组（`chunk_id`, `locator_kind`, `locator_label`, `excerpt`, `evidence_role`），`excerpt` 必须是父块原文的连续子串。候选原子集合 \(A\) 来自多路召回与关系补全。证据包 \(P \subseteq A\) 需满足：

\[
\sum_{a \in P} \mathrm{tokens}(a) + \text{parent metadata} \le B,\qquad
\mathrm{cover}(P, r)=1 \ \text{for every required } r \in R
\]

目标函数在预算内最大化必需关系覆盖，并对对象覆盖、证据多样性、重复文本、token 成本与来源分加权。冲突不是软惩罚，而是硬约束：同一冲突的双方要么同时入选，要么整体不入选并标记 `unresolved`。

## 3. 方法组成

### 3.1 短路径与动态预算

只看问题文本路由：

- `exact_record`：标识符 + 属性线索；基础 1,200 token、3 个父块、1 轮。
- `document_explanation`：版本/解释线索；基础 2,400 token、5 个父块、最多 2 轮。
- `cross_source`：两类及以上证据角色或跨资料线索；基础 3,600 token、8 个父块、最多 2 轮。

每多一个必需关系加 150 token，上限 6,000。第二轮只在某个必需关系零候选时触发，且只补缺失关系。生产预算不变，新增模块离线运行。

### 3.2 多路召回

1. `bm25`：问题原文与至多 4 个派生查询。
2. `row_exact`：结构化行索引，按标识符、端口区间、表头精确匹配。
3. `fact`：阶段二事实索引，按主体键、属性词与证据角色。
4. `revision`：版本题按显式修订或版本序号逐侧召回。
5. `literal`：数字、端口区间、百分比、稀有标识符的字面扫描，补 BM25 截断漏掉的数值/截图页。
6. `structure`：按表头/栏名定位结构表，补“栏为空/未填写”类证据缺口。
7. `neighbor`：同修订阅读序邻接块，只补解释上下文，不跨修订。
8. `dense`：E5/Qwen3 适配接口；离线回放记录 `available=false`，阶段四在 GPU 服务启用。
9. `graph`：关系补全引入的对端、角色、版本侧原子。
10. `archiver`：只读外部观测（可选）。

通道分数按 RRF（k=60）融合；BM25 与结构化分数不混用。每个通道调用与候选数写入轨迹。

### 3.3 关系补全

- 数值事实补同事实的单位与条件 citation；单位未知不猜。
- 关系事实补对端身份；无范围不跨柜连接。
- 角色矩阵：同一对象/属性的设计、测试、验收事实分别补入；角色缺失记为缺口。
- 测试范围：补 `test_scope` 过程事实或“测试条件/测量范围”参数事实。
- 版本侧：按修订顺序定义左/右；两侧同主题句子按字符 shingle 重合对齐，补两侧原文。
- 枚举：补目标表全部行；预算不足时标记不完整，不声称完整。

### 3.4 证据包选择

1. 冲突预选：双方同时入选；预算不足则双方均不入选并写 `unresolved`。
2. 版本对齐预选：至少保留一对对齐段落，供 `version_diff` 使用。
3. 贪心覆盖：按“新增必需关系 / token”选择；同时奖励对象实体覆盖、第二条证据来源、查询词覆盖。
4. 枚举进度：目标表每一行入选都增加收益，直到完整。
5. 预算填充：在覆盖关系后，用候选排名（或重排器分数）填充至 90% 预算，使小段落/行记录替代完整父块。
6. 局部改进：在不丢失关系与冲突双方的前提下替换低价值原子。

### 3.5 冲突处理

- 同一对象、属性、条件、证据角色、不同值 → 真冲突；设计值与测试值不同角色 → 角色差异，不是矛盾。
- 比较题并列保存两侧；核验题标记 `affects_target`，状态降为 `partial`，不得删除反对证据。
- `connectivity` 事实的端口区间是行键，同一设备不同行必然不同；跨表身份由 `exact_join` 的 `AMBIGUOUS_SCOPE` 拒绝处理，不按值冲突统计。
- 同一文档、同一表、同一角色的多行差异按不同行/不同项处理；这是当前限制。

### 3.6 规则版与学习版重排

规则版特征固定、可审计：对象实体匹配、查询词匹配、候选排名、角色匹配、表头匹配、单位/条件、重复、token、冲突；关系覆盖/范围/修订侧由证据包选择阶段处理，不重复进入重排特征。学习版是线性点式模型，特征相同，权重由 dev 族训练、val 族验证；标签来自 gold 最小证据，负例包括同题其余原子与构造的近似错误组合（交换相邻端口、加 `EXT-` 前缀的同名不同柜、删除条件子句、测试角色替换为设计角色）。

### 3.7 可执行核验

主张只来自证据包内的原子与事实/行。可用算子：`exact_join`、`port_range_membership`、`set_enumeration`、`unit_convert`、`boundary_compare`、`version_diff`。算子拒绝码原样保留；`ok` 只表示该输入上的确定结论，不表示整段回答已被形式化证明。

## 4. 实验设置（阶段三开发用）

- 语料：rc.3 只读快照；dev 10 个文档族、val 5 个文档族（互不重叠）。
- 题目：dev 100（68 deterministic）、val 50（36 deterministic）；rubric/human 只输出证据包与 `not_evaluated`。
- 对照：同一候选集合、同一 token 预算下的 `parent_top5`（生产形状，最多 5 个父块全文）。
- 稠密补充：生产同版权重 E5/Qwen3 在本机 CPU float32 上按生产 `PassageBuilder` 编码；passage contract 与生产索引一致，但不是生产 CUDA 索引。
- 指标：gold 证据块召回、全证据覆盖题数、gold 必要事实支持召回、平均 token、冲突成对保留、枚举完整、预算越界。
- 这些是**证据覆盖**指标，不是答案准确率；gold 只用于运行后评分，不进入检索、选择或回答。

## 5. 结果

| 划分 | 链路 | gold 证据块召回 | 全证据覆盖 | 必要事实支持 |
| --- | --- | ---: | ---: | ---: |
| dev | 证据包（lexical-only，基础） | 0.9571 | 61/68 | 0.9627 |
| dev | `parent_top5` | 0.7690 | 42/68 | 0.7823 |
| dev | 证据包 + 规则重排（lexical-only） | 0.9841 | 65/68 | 0.9876 |
| val | 证据包（lexical-only，基础） | 0.7917 | 23/36 | 0.7696 |
| val | `parent_top5` | 0.5718 | 15/36 | 0.5931 |
| val | 证据包 + 规则重排（lexical-only） | 0.8449 | 25/36 | 0.8382 |

- 同一预算下，证据包相对父块选择提高证据覆盖；规则重排进一步提高。这是描述性开发结果，未做 cluster bootstrap，不能表述为统计显著。
- deterministic 题平均 token 2,224—2,382，预算 2,627—2,683；平均引用父块 10.9—14.7，其中完整父块查阅引用 5.7—5.8。
- 冲突：dev 6/6、val 0/0 成对保留；枚举：15/15、5/5 完整；预算越界 0。
- gold 补丁口径：5 条补丁中 3 道 dev/val deterministic 题的 `required_facts` 为纯字符串、没有 `support` 列表；上表支持率按 67/68 与 34/36 道可用题计算。在相同可用题集合上，补丁前后的支持率逐题相同；gold 召回、全证据覆盖、路由与 verification 状态均未变化。若按 `evidence_minimal` 支撑字符串事实，则支持率与原值一致。
- 学习重排：val AUC 0.8459 vs 规则 0.8497；precision@10 0.1889 vs 0.2278。未优于规则版，保留规则版，不宣称通用贡献。
- 真实稠密通道补充（生产同版权重、本机 CPU float32、passage contract 与生产索引一致；不是生产 CUDA 索引）：基础版 dev 的 lexical-only/E5/Qwen3/E5+Qwen3 召回为 0.9571/0.9718/0.9718/0.9645，val 为 0.7917/0.7986/0.7801/0.7894；加规则重排后 dev 为 0.9841/0.9877/0.9877/0.9877，val 四组均为 0.8449。稠密通道在 dev 有小幅提升，val 没有稳定增益；论文不得把 lexical-only 数字称为 full chain，也不能声称 E5/Qwen3 必然提高 val。逐项表见 `docs/research/phase3/README.md` §4.6。

## 6. 论文中的定位与边界

- 本节贡献是**选择对象的改变**与**关系可复核的证据组合**，不是新的嵌入模型或新的生成模型。
- 与 TableRAG、S2G-RAG、TechDocRAG 等工作的关系：本文不主张“表格入库”“缺口驱动补检索”或“技术文档建图”本身；差异点在对象身份、证据角色、条件/端点与可执行核验的组合，且阶段四才做与这些基线的公平对比。
- Archiver 只作为扩展证据适配器；主结果不依赖联网观测。单次探针不能证明新系统优于基线。
- 当前证据是 dev/val 上的机制结果，不是独立盲测；论文结论须等阶段四的完整对比、消融、配对干预与跨族迁移。

## 7. 有效性威胁

1. **标签泄漏风险**：检索不读 gold；但训练学习版使用 dev gold，必须在论文中明确并按族划分。
2. **范围提示**：题目 `family_ids` 作为检索范围，所有方法相同；真实部署中范围可能来自用户或系统，需另报“全库检索”设置。
3. **证据覆盖≠答案正确**：覆盖 gold 证据不等于结论正确；阶段四以任务级正确且证据充分率为主指标。
4. **冲突检测粒度**：阶段二事实的主体/条件字段有限，部分冲突可能漏检或误检；报告已给出限制。
5. **token 估计器**：离线估计器与生产 tokenizer 不同；阶段四必须用生产 tokenizer 重跑。
6. **样本量**：val 36 道 deterministic、5 个族，置信区间宽；不能据此宣称泛化。
