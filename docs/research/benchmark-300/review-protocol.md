# 300 题基准独立审核协议（R1—R5）

日期：2026-11-07。适用范围：`data/evaluation/research-benchmark-300-v1/` 下全部题目、真值、证据与干预，以及 `docs/research/benchmark-300/` 下的规范与划分政策。

## 1. 审核原则

1. **独立性**：审核代理不得参与出题、标注或组装；各自独立上下文；只读，不修改任何题目、规范或代码。
2. **从严默认**：无法从原文复算的 gold、无法定位的证据、跨划分的对象关系，一律按阻断处理；不得以“可能没问题”放行。
3. **可复核**：每条 finding 必须给出 `base_id`（或文件/字段）、问题描述、判定理由、原文或 chunk 依据。禁止只给笼统意见。
4. **只出意见**：审核代理不提供改好的题目，只指出问题与修复方向；修复由对应工作流执行。

## 2. 分级

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| 阻断 | 真值错误、证据不可复算、跨划分泄漏、规模/配额不达标、违反方案口径 | 必须修复并重审 |
| 重要 | 证据非最小、分类可疑、题型与场景不匹配、干预不成对但可修 | 修复后复审该题 |
| 建议 | 表述、覆盖、可读性、统计说明不足 | 记录，酌情采纳 |

规则：同一题被两个及以上审核代理判为阻断，退回对应出题工作流重做该题（不是只改字段）。

## 3. 输入

- 规范：`docs/research/benchmark-300/SPEC.md`
- 划分政策：`docs/research/benchmark-300/split-policy.json`
- 方案：`docs/research/rag-research-reset-20261107.md`
- 题目：`data/evaluation/research-benchmark-300-v1/{dev,val,sealed-test}/questions.json`（R1、R2、R5 可读全部；R3 必须读全部以检查泄漏；R4 读规范与统计）
- 结构校验与审计：
  - `python3 scripts/research/validate_benchmark.py --all`
  - `python3 scripts/research/audit_benchmark.py`
  - `data/evaluation/research-benchmark-300-v1/stats.json`
- 语料：`python3 scripts/research/rc3_query.py ...`（只读）

## 4. 分工与检查清单

### R1 独立性审核

- 底题是否按对象关系与来源划分：每题的锚点（电缆、机柜、端口块、功能点、要求—测试对、修订序列）是否唯一且互不重复。
- 改写、翻译、改一个数值、换一种问法是否被当成新底题；这类变体是否只出现在同一 `base_id` 的 `interventions` 中。
- 同一底题的全部扰动是否共享 `base_id`；是否存在同一事实被拆成多道“独立”题。
- 同一 `interventions` 是否被复制到不同底题；干预目标 chunk 是否被多题共用。
- 判读口径：同一父块被多道题引用不自动构成重复。要求—测试核验题经常引用同一段设计要求或同一张测试结果表；只要每道题对应不同的要求—测试对、且题干与判定实质不同，就应视为独立底题。仅在题干与判定实质相同、或仅替换对象名称而答案结构完全一致时，才判重复。
- 输出：重复/近重复清单、共享锚点清单、应合并题号。

### R2 真值审核

- 逐题抽查 gold 能否仅用 `evidence_minimal` 复算；`recompute_note` 是否真的可执行。
- 证据是否最小且充分：删除任一 `fact_support` 后是否有 fact 失去支撑；是否存在未被任何 fact 引用的证据。
- `excerpt` 是否逐字来自 chunk；是否用 `……` 掩盖了不连续或改写。
- `verdict_class` 是否正确：deterministic 是否真的可机械复算；rubric/human 是否被滥用或错分。
- 数值、单位、版本归属是否正确；是否把设计值当测试值、把验收结论当测试数据。
- 扫描/OCR 证据（`pymupdf-blocks-v1`）是否被用于支撑数值；是否有页面核对记录（`ocr_verified`）。
- `partial`/`insufficient` 题是否写清缺什么，而不是含糊其辞。
- 输出：逐题判定（通过/阻断/重要）、不可复算清单、最小性反例。

### R3 泄漏审核

- test 文档族与对象簇是否与 dev/val 完全隔离（双向）。
- 是否存在同一连接链、同一要求—测试对、同一修订序列（含归档副本）跨划分。
- 是否通过共享交换机配置、汇总表、设计报告等间接文档把 test 对象带入 dev/val（或反向）。
- `interventions` 的目标 chunk 是否跨划分。
- 30 道显式修订范围题是否只在 test 内部或按政策分布，不构成对 test 答案的提示。
- 输出：跨划分族/对象/链清单、泄漏路径说明、受影响题号。

### R4 方案一致性审核

- 第 2.1 节：现有 100 题是否全部归入已曝光开发与回归材料，不再保留 sealed 含义；30 道版本题是否显式传入修订范围并标记为与全库检索分开报告。
- 第 7.1 节：底题是否按对象关系与来源划分；翻译/改写/改数值是否未计为独立样本；划分单位是否为文档族与相关对象簇。
- 第 9 节：资料范围是否为 225 个登记修订；3 个受限修订是否只用于原访问范围（默认证据不得引用）。
- 第 10 节：测试集是否阶段一即物理隔离；是否保持未见文档族与未见对象簇；本阶段是否未进入事实层与算子研发（无代码能力改动）。
- 第 5 节：三类场景定义与题目是否一致；场景三是否给出要求—测试配对清单与覆盖不足时的处理。
- 输出：违反条款清单、对应题号或文件、修复要求。

### R5 统计与规模审核

- 三类是否各约 100 题；100/50/150 是否精确落实；各 cluster 配额是否满足。
- 配对干预是否成对（每题 ≥1 should_change、≥1 should_hold）；干预类型分布是否覆盖方案第 7.4 节。
- 30 道显式范围题的划分分布是否为 10/10/10。
- 置信区间所需样本量是否有说明：主指标为配对二分类时，150 题能检出的效应量、聚类 bootstrap 的设计效应、每类 50 题的探索性定位。
- `stats.json` 与题目文件是否一致；是否存在为凑数产生的低信息题。
- 输出：规模表、配对表、样本量说明缺口、需调整的配额或题号。

## 5. 结论与复审

- 每个审核代理给出总判定：`通过` 或 `不通过`，并列出阻断数、重要数、建议数。
- 存在阻断即总判定 `不通过`。
- 修复后由原审核代理复审阻断项；复审通过才计入最终通过。
- 最终交付前 R1—R5 必须全部给出 `通过`。

## 6. 禁止事项

- 不得修改题目、真值、证据、干预、规范、划分政策或代码。
- 不得用模型自评代替原文核对；不得把“看起来合理”当作通过理由。
- 不得引用未在 rc.3 快照中的 chunk 或修订。
