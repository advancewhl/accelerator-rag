# 工作台与新格式阅读改进计划

日期：2026 年 11 月 2 日。状态：配套设计，尚未实施。主任务见[新批次文档类型检查与改进计划](new-document-types-review.md)。

目标是让用户在工作台中完成“找到资料、选定范围、提出问题、核对原文”。优先解决今天新增资料看不了和查阅范围不清的问题。

## 1. 为什么好多新文档看不了

**多数新增资料打不开，直接原因是新格式的阅读链路尚未接入。** 这与文件是否已被解析、是否进入索引是两回事。

按已保存生产构建记录和当前格式支持范围，207 份修订中，52 份为 PDF／Markdown，155 份为 DOCX、DOC、PPTX、XLSX。后面 155 份全部来自今日新增资料。

| 位置 | 当前行为 | 用户看到的结果 |
| --- | --- | --- |
| 文档目录 | 只对 PDF、Markdown 提供 `document_url` | 新格式的阅读按钮不可用 |
| 回答引用 | 非 PDF／Markdown 的 `document_url` 为 `null` | 引用可显示段落或幻灯片位置，但打不开 |
| `/view` 接口 | 新格式返回 `READER_NOT_IMPLEMENTED` | 没有对应阅读页面 |
| 原文件接口 | 非 Markdown 当前仍统一声明为 PDF | 不能直接把该接口当作 Office 原件下载入口 |

前端的“该格式阅读页未接入”实际上反映了已有能力缺口。单纯改按钮文案、显示文件扩展名或刷新目录不能解决。

本次依据本地实现和已保存构建记录判断，未重新逐一访问线上文件。52 份表示格式已有阅读支持，不代表本次逐一确认过文件链接可用。

依据：[目录](../../src/accelerator_rag/rag/catalog.py)、[原文接口](../../src/accelerator_rag/rag/api.py)、[引用生成](../../src/accelerator_rag/rag/answer.py)、[工作台前端](../../src/accelerator_rag/rag/web/app.js)。

## 2. 第一优先：补齐各格式的实际阅读能力

| 格式 | 工作台阅读方式 | 引用定位 | 原件入口 |
| --- | --- | --- | --- |
| DOCX | 先用本次入库的规范化正文提供结构化阅读，补充图片和表格；可靠时提供 PDF 排版预览 | 段落或表格锚点，保留上下文 | 下载原始 DOCX |
| DOC | 阅读转换件，明确标注原始格式 | 转换后的段落锚点 | 下载原始 DOC，同时可取得转换件 |
| PPTX | 幻灯片预览、缩略图和同页文本；备注单列 | 幻灯片序号及命中对象 | 下载原始 PPTX |
| XLSX | 工作表切换、冻结表头、命中行高亮 | 工作表与单元格范围 | 下载原始 XLSX |
| 扫描 PDF | 原页与 OCR 文字对照 | 物理页，后续补区域定位 | 保留 PDF 原件 |

阅读器优先使用与本次入库一致的内容快照。避免点击引用时临时重新解析另一版内容，导致锚点变化。

第一步就提供正确格式的原件下载，解决“只能看文件名”的问题；同时接入规范化正文阅读。派生 PDF 或幻灯片预览需要后续生成，但不能用不存在的页码充当定位。

Word 公式使用有效 LaTeX 源码和兼容渲染器。字号匹配正文，并核对上下标、分式和裁切。尚未恢复的公式区域以原图核对，明确标识其状态。

## 3. 第二优先：让目录说明资料能怎么用

当前目录给文档统一显示“已收录 · 可检索”，但历史和待核实资料默认不参与问答。需要分开显示以下状态：

- 资料已收录。
- 默认问答可用，或需要选择历史／待核实范围。
- 在线阅读可用，或暂仅提供原件下载。

默认问答有 121 份资料可参与；另外 86 份为历史或待核实资料。这些数量来自当前登记表与生产修订集合的关联统计。工作台应读取服务提供的实际范围，避免把这些数量写死。

目录优先增加格式、业务类型、版本状态和主题筛选，提供“今天新增”“操作手册”“设计资料”“表格”快捷入口。搜索支持标题、别名和版本标签。

同一设备的同一文档按版本折叠。不同设备的操作手册继续分别展示，不能因为同属手册系列而合并为一个文档的版本列表。

## 4. 第三优先：把资料选择接到问答

文档详情提供“在本资料中提问”和“加入本次查阅范围”。发送问题时，同时传入实际选中的修订，而不只把标题拼到问题文字中。

输入框上方显示范围标签，例如“全部默认资料”“本手册第三版”“含历史说明”。标签可移除，切换范围后明确提示下一次查询使用的新范围。

选择待核实材料时，可以回答这份材料的内容，但回答和引用继续显示文档状态。工作台不应让用户误以为选中文档就代表该版本已确认现行。

后续版本比较使用独立的两侧选择。当前服务尚未实现 `compare` 模式，因此暂不展示可以点击却无法完成的比较按钮。

## 5. 建议的工作区布局

沿用现有问答与右侧证据布局，先扩展内容，不优先进行整页视觉重做。

| 区域 | 内容 | 主要交互 |
| --- | --- | --- |
| 资料目录 | 筛选、最近新增、文档与版本 | 打开资料、选择查询范围 |
| 问答区 | 当前范围、问题、答案和缺失信息 | 在所选资料中提问，点击引用 |
| 原文区 | 格式对应的阅读器、命中位置及上下文 | 高亮、前后段／页切换、原件下载 |

在桌面端允许扩大原文区宽度；在窄屏上切换问答和原文。切换资料或回到目录时保留已输入问题、筛选条件和阅读位置，减少反复查找。

引用卡显示标题、版本、资料性质、准确位置和短摘录。段落、幻灯片和单元格分别使用对应名称，不统一称为“页”。OCR 和备注状态在相关引用处显示。

## 6. 实施顺序与完成标准

| 顺序 | 工作 | 用户可见的完成标准 |
| --- | --- | --- |
| W1 | 原件下载、格式与内容类型 | 新格式文档能取得正确的原文件 |
| W2 | DOCX／DOC 结构化阅读、PPT 页面阅读、XLSX 单元格阅读 | 点击引用能到对应段落、幻灯片或单元格 |
| W3 | 目录状态、格式筛选、最近新增 | 用户看得出已收录资料的阅读和查询方式 |
| W4 | 单文档／多文档范围与输入框标签 | 问答实际使用所选资料范围 |
| W5 | 图片、公式、OCR 对照和阅读位置保留 | 用户能核对复杂内容，往返阅读不丢位置 |

W1、W2 直接解决当前“新增资料看不了”的问题。W3、W4 与主计划中的资料范围和文档族完善相配合；W5 跟随各格式内容恢复逐步完成。

完成后，用户从目录选一份新增资料，可以打开正文、定位命中内容、在该资料范围内提问，再回到原文核对。仅增加格式图标或文档数量，不算完成这项工作。
