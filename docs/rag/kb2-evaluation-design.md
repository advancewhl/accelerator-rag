## 1. 目的、范围与证据边界

### 1.1 目的

`kb-2.0.0` 的验收要回答三类问题：

1. 新资料入库后，系统能否回答定时、恒温机柜、激光、真空、PDU、数据存储/存档等新主题的事实与操作题。
2. 系统能否区分当前、历史、草稿和待核实修订，并在版本比较题中分别给出两侧依据和适用条件。
3. 系统能否在 OCR、表格、幻灯片、公式和资料边界场景中给出可定位、可核对、不过度推断的答案。

新增 60 题是首版验收集的**规划值**。按总体计划 §11.1，具体题目应在代表样本解析后冻结；当前 JSON 的 `status` 为 `draft`，所有题目的答案边界和证据位置都还不是最终金标准。

### 1.2 证据分级

JSON 中每题只有一个 `provenance_status`，含义如下：

| 状态 | 含义 | 使用规则 |
| --- | --- | --- |
| `verified_from_extracted_text` | 具体数值/表述已在 `reports/incoming-2026-11-02/tmp/doc-txt/` 的可读正文中核对 | `notes` 必须给出原文片段或明确章节位置；可直接作为当前规划答案边界 |
| `derived_from_analysis` | 数值/表述来自 `ANALYSIS.md`、总体计划或 `inventory.clean.json` 的二手摘要/文件头 | 不得当作原文引用；`notes` 必须说明来源和“需回原文核对”；冻结前必须升级为原文核实或降级为 `needs_source_check` |
| `needs_source_check` | 目标 DOCX 表格、PPTX 幻灯片、扫描 PDF OCR 或 V6 公式尚未提取/复核 | 题目只能用于规划；`evidence_location` 可为 `unknown` 或工作表/章节级；冻结前必须补齐页码/幻灯片/单元格并人工复核 |

当前规划计数：**39 题 `verified_from_extracted_text`、8 题 `derived_from_analysis`、13 题 `needs_source_check`**。

`reports/incoming-2026-11-02/tmp/doc-txt/` 现有 **15 份可读正文**。批次清单中对应 16 个 `.doc` 路径，其中 `操作手册/~$INE激光界面操作手册.doc` 是 Office 临时锁文件，不产生可引用正文。因此本规划只把 15 份正文当作可直接引用的证据；未提取的 V6、联锁/总控等设计报告、PPTX、XLSX 和扫描 PDF 全部标为 `derived_from_analysis` 或 `needs_source_check`。

### 1.3 不做什么

- 不把 `ANALYSIS.md` 的二手描述当作原文引用；所有引用 `ANALYSIS.md` 的题都标为 `derived_from_analysis`，并注明需回原文核对。
- 不编造页码、幻灯片序号、单元格地址、版本号、批准人或现场值。
- 不把设计值、样机实测值、现场运行值混为同一口径。
- 不把新增 60 题包装成独立科研测试集；题与资料同源，存在来源重叠。

## 2. 评分口径

### 2.1 评分单位

以**单题任务**为评分单位，不以句子或关键词为单位。每题至少由一位熟悉资料的业务审核人评分；版本冲突、数值争议和评分分歧由第二位审核人裁决。助理生成的评分只能作为待复核意见，不能替代人工结论。

冻结时每题还必须标注 `expected_status`，取值为 `answerable` / `partial` / `insufficient`。当前新题 JSON 用 `expected_answer_boundary` 文本表达边界，尚未写入枚举字段；评分前由审核人把边界映射为状态，冲突题按“是否仍存在可核实部分”映射为 `partial` 或 `insufficient`，并记录映射理由。没有 `expected_status` 的题不得进入正式评分。

### 2.2 什么算“任务通过”

一道题的 `task_pass` 为真，必须同时满足：

1. **必要事实齐全**：`required_facts` 全部出现；数值、单位、比较符（`<`、`≤`、`>`、`≥`）、正负号和有效位数正确。
2. **条件完整**：`task_condition` 要求的前提、适用设备/系统、测量/设计口径、时间范围全部说明；不把条件省略成无条件结论。
3. **操作顺序正确**：操作题必须按原文顺序给出步骤，特别是使能/触发/退出、开关机、参数保存等顺序；不得省略安全或收尾步骤。
4. **适用版本正确**：默认查询使用现行依据；指定版本/历史查询使用对应修订；版本比较题分别列出两侧修订和适用条件；不得把旧版、草稿、待核实或未批准材料说成当前事实。
5. **无禁止推断**：不出现 `forbidden_inferences` 中的断言；不把“资料没有记载”扩大为“能力不存在/现场没有部署”。
6. **引用支持关键断言**：每个关键事实能由对应修订的引文支持；引用必须定位到页码、章节、幻灯片、单元格或行号，不能只给整篇文档链接。仅“链接能打开”不算通过。

任一条不满足即 `task_pass = false`。一般措辞、重复背景、格式不美观不计为关键错误，单独记录为 minor issue；不能用一个总分掩盖关键错误。

### 2.3 关键错误类型

以下四类为关键错误，出现任一即该题不通过：

| 错误类型 | 定义 | 典型例子 |
| --- | --- | --- |
| 错误参数 | 数值、单位、比较符、正负号、有效位数或适用量纲错误 | 把 `<10 µs` 写成 `≤10 ms`；把 8 GeV 写成 7.2 GeV；把 80% 写成 50% |
| 错误操作顺序 | 步骤顺序颠倒、遗漏使能/确认/保存/退出步骤，或把不同修订的步骤拼接 | 单触发模式未退出就恢复运行；把第一版的 APPLY 步骤套到 2023-09 版 |
| 错误适用版本 | 把旧版、草稿、待核实、未批准或样机材料说成当前/已批准/现场依据；版本比较只给一侧 | 把“返回通读版本”V6 说成正式现行版；把 2018 初步设计 8 GeV 当作当前唯一值 |
| 无依据的现场状态断言 | 编造当前温度、频率、设备在线状态、部署版本、批准状态、根因或修复证明 | “今天 8 台恒温机柜温度正常”；“网络安全报告已批准”；“PLC 故障是唯一根因” |

另外两类**门禁失败**单独统计，不混入四类关键错误：

- **引用不支持**：关键断言有引用，但引文不包含该事实，或引文属于错误修订/错误位置。
- **评分歧义**：题干、证据或答案边界本身有歧义，需裁决；不能把歧义题计为模型错误。

### 2.4 部分通过

部分通过只适用于 `expected_answer_boundary` 明确要求“部分回答/说明缺项”的题，或旧 50 题中 `expected_status = partial` 的题。

判定规则：

1. **可核实部分正确**：已给出的部分满足 2.2 的必要事实、条件、版本和引用要求。
2. **缺项说明完整**：明确指出哪些信息资料不足、需要什么补充证据、为什么不能给出目标结论。
3. **不越界**：不把部分结论扩大为完整结论，不编造缺失事实。
4. **整题拒答不算部分通过**：如果题目存在可核实部分，整题拒答会遗漏已有信息，应判为未通过或 partial 未达成；若题目本身完全缺证据，则按 2.5 的拒答规则判。

### 2.5 拒答与资料不足的判定

| 题目预期 | 回答行为 | 判定 |
| --- | --- | --- |
| 可回答 | 给出完整正确事实 | 通过 |
| 可回答 | 整题拒答 | 不通过（错误拒答） |
| 可回答 | 给出部分事实但漏关键条件 | 不通过或 partial，视缺项是否属于 `required_facts` |
| 部分可回答 | 给出可核实部分 + 明确缺项 + 不越界 | 通过 |
| 部分可回答 | 整题拒答 | 不通过（遗漏已有信息） |
| 部分可回答 | 给出部分事实但把缺项说成确定结论 | 不通过（无依据断言） |
| 完全缺证据 | 明确说“本次资料不能确认”，说明需要什么证据，不编造目标事实 | 通过（正确拒答） |
| 完全缺证据 | 提供相关背景但明确与目标事实分开 | 通过，前提是没有暗示已回答目标事实 |
| 完全缺证据 | 编造数值、部署状态、批准状态、根因或修复证明 | 不通过（关键错误） |
| 存在冲突 | 列出两侧修订/数值/条件，说明“存在冲突/资料不足”，不强迫单一结论 | 通过 |
| 存在冲突 | 强行选择一侧作为唯一现行值，且无批准/替代依据 | 不通过（错误适用版本） |

对冲突题，**“资料不足/存在冲突”是允许的正确回答**，不得在评分时强迫模型给出单一结论。只有资料责任人已经确认替代关系或批准状态时，才允许给出单一现行值；该确认必须作为证据记录。

### 2.6 评分记录字段

每题至少记录：

| 字段 | 取值/说明 |
| --- | --- |
| `task_id` | 如 `KB2-FACT-001` / `P50-001` |
| `split` | `dev` / `sealed` / `old50` |
| `reviewer` | 审核人标识 |
| `strict_correct` | 必要事实、数值、比较符、单位、条件、版本全部正确 |
| `task_pass` | 按 2.2 的布尔结论 |
| `partial_coverage` | 部分题的可核实部分是否覆盖、缺项是否说明 |
| `boundary_correct` | 拒答/资料不足/冲突题是否正确限定 |
| `critical_errors` | 四类关键错误列表；为空表示无 |
| `citation_supported` | 每个关键断言是否有对应修订和位置的引文支持 |
| `failure_stage` | `source_missing` / `parse_or_ocr` / `retrieval` / `context_or_condition` / `version_selection` / `generation` / `scoring_ambiguity` |
| `notes` | 多因解释、裁决记录、minor issue |

## 3. 分组计划

新增 60 题分四组，计数严格为 **20 / 15 / 15 / 10**；开发 40、封存 20。

| 组 | 计划题数 | 开发/封存 | 题号段 | 验证重点 |
| --- | ---: | ---: | --- | --- |
| `new_facts_operations` 新资料事实与操作 | 20 | 14 / 6 | `KB2-FACT-001`～`020` | 定时、恒温机柜、激光、真空、PDU、数据存储/存档客户端的事实与界面操作；含 2 道 V6 总体事实 |
| `version_comparison` 当前/历史/版本比较 | 15 | 10 / 5 | `KB2-VER-001`～`015` | 操作手册第一/二/三版与归档版、2023-09/2024-11 客户端、设计报告与 V6/样机口径 |
| `format_evidence` OCR/表格/幻灯片/公式 | 15 | 10 / 5 | `KB2-FMT-001`～`015` | 表格单元格、幻灯片序号、扫描 PDF 页码、公式 LaTeX、DOCX 表格表名/表号 |
| `conflict_boundary` 冲突/未知/资料边界 | 10 | 6 / 4 | `KB2-BND-001`～`010` | 待核实日期、未批准修订、设计/实测/现场区分、缺证据、导出限制与保留期区分 |
| **合计** | **60** | **40 / 20** | | |

### 3.1 格式证据的分布

`format_evidence` 15 题内部覆盖：

| 证据类型 | 题数 | 题号 |
| --- | ---: | --- |
| 表格/结构化数据（DOCX/XLSX） | 6 | `FMT-001`、`002`、`003`、`004`、`014`、`015` |
| PPTX 幻灯片/备注 | 4 | `FMT-005`、`006`、`007`、`008` |
| 扫描 PDF OCR | 4 | `FMT-009`、`010`、`011`、`012` |
| 公式（V6 DOCX） | 1 | `FMT-013` |

其中只有 `FMT-001`、`FMT-002`（数据存储报告的服务器配置/目录结构）已从提取正文核实；其余 13 题均标 `needs_source_check`，冻结前必须补齐页码、幻灯片序号或单元格范围。

### 3.2 开发集与封存集

- **开发集 40 题**：用于解析、检索、提示词和策略诊断；可以查看逐题失败并修复受影响分组。
- **封存集 20 题**：在提示词和检索策略调整前封存，由业务审核人出题或确认；最终候选冻结后才运行并报告。封存题一旦用于调参，即退回开发集，并补充新的封存题，不能把同一题同时算作开发与封存。
- 封存集数量按组分配为 6/5/5/4（对应 FACT/VER/FMT/BND），不是按难度分层；业务审核人可在冻结时调整组内分布，但总数 20 和组计数 20/15/15/10 不得改变。

## 4. 旧 50 题与新增 60 题的报告方法

### 4.1 旧 50 题

旧题集为 [`data/evaluation/validity-pilot-v2.json`](../../data/evaluation/validity-pilot-v2.json)，共 50 题：45 道 `answered`、3 道 `partial`、2 道 `insufficient`；分类为 10 道 PDF 对照、15 道条件、10 道版本、10 道诊断、5 道边界。

报告要求：

1. **沿用同一评分口径**（第 2 节），不改旧题结构、不覆盖旧评分记录。
2. **分别报告**总体、五个类别和三种预期状态；不得只用接口成功率代替语义通过率。
3. **旧题期望答案修订必须绑定 `kb-2.0.0` 语料范围**，不能事后改答案提分。具体见 4.3。

### 4.2 新增 60 题

报告要求：

1. **开发集 40 题先报告**：按四个组给出题数、通过数、部分通过数、失败数、正确拒答数、错误拒答数、关键错误数、引用支持率和失败阶段分布。
2. **封存集 20 题单独报告**：在最终候选冻结后运行；不与开发集合并成一个“总通过率”。若封存集被用于调参，报告必须标注已污染，并补充新封存题。
3. **按预期状态拆分**：可回答、部分可回答、完全缺证据/冲突题分别给分母；不能把拒答题计入可回答题的分母。
4. **按格式/证据类型拆分**：表格、OCR、PPTX、公式、DOCX 事实、版本比较分别给出失败案例；解析/OCR 失败与检索/生成失败分开归因。

### 4.2.1 100 题工程回归集（2026-11-05）

`data/evaluation/kb2-benchmark-100-v1.json` 是 **rc.3 与 rc.2 的工程对照集**，不是本文件定义的 K5 验收题集，也不替代 60 题。组成：旧 50 题（`validity-pilot-v3`，只补充 8 道题干范围）、线缆 20 题、60 题草案中 30 道 `verified_from_extracted_text` 题。它的用途是比较 HTTP 稳定性、预期状态、引用定位和延迟，并暴露题集自身的问题；语义通过率仍按第 2 节人工评分。核验与排除理由见[核验报告](../../reports/benchmark-100-20261105/README.md)。

60 题草案的 13 道 `needs_source_check`、8 道 `derived_from_analysis` 和 2 道依赖受限资料的题不进入工程回归。它们的 `expected_status` 也尚未由业务审核人映射，不能因为进入 100 题就视为已冻结。

### 4.3 旧题期望答案修订规则

旧题保留原始题集和评分记录。另建**绑定 `kb-2.0.0` 语料范围的期望答案修订**，建议命名 `old50-expected-revision-kb2.0.0-v1.json`（待 K5 实施时创建）。这里的“语料范围”以发布清单中的文档族/修订集合为准，不以“本批 218 个输入文件”或“新增 60 题来源”代替；旧题只有在明确纳入该修订集合的新证据出现时，才允许修改答案边界。修订记录至少包含：

| 字段 | 内容 |
| --- | --- |
| `release_id` | `kb-2.0.0` |
| `build_id` | 候选构建号 |
| `corpus_manifest_sha256` | 发布清单/语料范围哈希 |
| `question_id` | `P50-001` 等 |
| `old_expected_boundary` | 原题集答案边界，逐字保留 |
| `new_expected_boundary` | 绑定 `kb-2.0.0` 后的答案边界 |
| `change_type` | `no_change` / `new_evidence` / `scope_restriction` / `conflict_unresolved` / `question_ambiguous` |
| `evidence` | 新增证据的文档、修订、位置、摘录 |
| `reviewer` / `reviewed_at` | 业务审核人及日期 |

冻结规则：

1. 修订必须在**候选问答运行前**完成并冻结；冻结后不得因看到得分而修改。
2. 每个答案变化必须由新增证据解释；不能为了提高得分放宽答案边界、删除必要事实或把错误答案改成“拒答”。
3. 旧结果继续绑定旧题集/旧修订；新结果绑定新修订。不得覆盖旧结果后声称是同一冻结实验。
4. 若冻结后确需修改，产生新的修订号，并重跑所有受影响题目；报告中并列旧/新修订与差异。
5. 旧题中因新增资料从“资料不足”变为“可回答”的，属于 `new_evidence`，必须记录新增证据；不能只把状态从 `insufficient` 改成 `answered`。

### 4.4 组合报告

组合报告不是把旧 50 与新 60 简单相加成一个百分比。建议矩阵：

| 维度 | 旧 50 | 新 60 开发 | 新 60 封存 |
| --- | --- | --- | --- |
| 可回答题通过率 | 分子/分母 | 分子/分母 | 分子/分母 |
| 部分题通过率 | 分子/分母 | 分子/分母 | 分子/分母 |
| 边界/拒答正确率 | 分子/分母 | 分子/分母 | 分子/分母 |
| 关键错误数 | 计数/题数 | 计数/题数 | 计数/题数 |
| 引用支持率 | 分子/分母 | 分子/分母 | 分子/分母 |

组合报告同时给出：

1. **微平均**：可回答题合并分子/分母；仅用于总览，不能替代分组。
2. **宏平均**：先算每组通过率，再对组等权平均；用于防止题量大的组掩盖弱组。
3. **回归表**：基线通过、候选失败的旧题；区分“旧库无证据”与“旧库答错”。
4. **关键错误表**：四类关键错误逐题列出，不因总体通过率高而省略。
5. **审核分歧表**：两位审核人结论不一致的题、裁决人和最终结论。

若必须给出一个组合头条数字，使用**分层宏平均**：旧题按五个类别、新题按四个组，先算层内通过率，再对层等权平均；同时附微平均、各层分母和封存集单列结果。不得只给一个未分层的百分比。诊断阶段的组合以“旧 50 + 新 60 开发集”为主；封存 20 题在最终候选冻结后单列报告，不参与调参，也不并入诊断期头条数字。

组合报告的门槛仍按总体计划 §11.2：新增可回答题人工任务通过率目标至少 90%；版本与边界关键题必须全部通过；原有已正确案例不得新增关键错误。90% 是上线质量目标，不是预测准确率，也不证明统计显著收益。60 题不是科研样本，报告中只给计数、分母和失败案例，不声称统计显著性。

## 6. 上线报告模板与门槛

每个候选版本至少输出：

1. **题集身份**：题集 revision、`release_id`、`build_id`、语料清单哈希、封存状态。
2. **分组结果表**：组、题数、通过、部分通过、失败、正确拒答、错误拒答、关键错误、引用支持率。
3. **逐题表**：题号、预期状态、实际结论、关键错误、失败阶段、引用是否支持、审核备注。
4. **失败归因**：资料缺失、解析/OCR、检索、条件补全、版本选择、生成、评分歧义，多因可并列。
5. **回归与差异**：旧 50 通过/失败变化；新增资料导致的期望答案修订；旧库无证据 vs 旧库答错的区分。
6. **门槛结论**：按 §11.2 逐项给“通过/未通过/未测”，不拿未测项填成通过。

性能、阅读器和发布恢复指标单独报告，不混入语义通过率。现有 2026-10-30 P95 31.0 s 只作历史参考，正式比较使用同机器、同模型服务、同并发的新基线。

## 7. 已知限制

1. **证据覆盖不完整**：当前只有 15 份可读提取正文，主要是操作手册和少量数据存储/存档设计报告；V6、联锁/总控等设计报告、PPTX、XLSX、扫描 PDF 均未解析。39 题已核实、8 题二手推导、13 题待核，不能把当前 JSON 当作完整验收集。
2. **同源重叠**：新题与新增资料来自同一批材料，题目编写者可能已知答案；这不是独立科研测试集。封存集只能降低调参污染，不能消除来源重叠。
3. **旧 50 语义评分未完成**：不能把接口成功率当作准确率基线；旧题期望答案修订必须在候选问答前冻结。
4. **不回答现场状态**：所有题都基于静态文档；涉及“今天/当前/现场”的问题必须按资料边界拒答或要求实时数据，不能从文档日期推断。
5. **60 是规划值**：代表样本解析后可能发现题目不可答、证据不足或重复，届时按组计数调整并记录修订；不能为了凑数保留无证据题。
