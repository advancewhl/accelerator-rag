# 50 题有效性边界验证协议

本协议对应[当前研究计划](../../PRAB_PLAN.md)和[题集 v2](../../data/evaluation/validity-pilot-v2.json)。题集版本为 `2026-10-29-r1`，共 50 题，仅供开发诊断。旧 `seed-questions-v1*.json` 保留为历史材料，不能继续使用其核验标签。

执行更新：2026 年 10 月 30 日已完成 Markdown 生产发布和 50 题线上运行。原始响应、完整 trace、离线覆盖统计与助理初审见[执行报告](../../reports/validity-pilot-online-20261030/README.md)。本轮暴露的题干／清单歧义见[裁决清单](../../reports/validity-pilot-online-20261030/rubric-adjudication.md)，独立人工评分仍待完成。

## 1. 这轮要回答什么

先判断证据能否进入检索和准确引用，再判断系统有没有遗漏适用条件、混用版本或超出证据归因。表格格式损坏属于解析问题，不单列为创新收益。

本轮题集包含 10 道已有 PDF 题和 40 道重新编写的 Markdown 题。后者依据已重写文档，未沿用旧题摘录。文档与问题由同一轮材料整理而来，存在来源重叠；全部题目都不是独立测试集。

| 类别 | 题号 | 数量 | 主要检查 |
| --- | --- | ---: | --- |
| PDF 对照 | P50-001～010 | 10 | 已有知识、条件、比较符和多证据要求 |
| 数据与分析适用条件 | P50-011～025 | 15 | 数据身份、掩码、时基、频率和分析前提 |
| 版本与历史解释 | P50-026～035 | 10 | 接口变化、版本范围和部署不确定性 |
| 故障定位与证据组合 | P50-036～045 | 10 | 观察、定位、根因和处理顺序 |
| 证据边界 | P50-046～050 | 5 | 2 道无法给出目标结论，3 道应部分回答 |

预期状态合计为 45 道 `answered`、3 道 `partial`、2 道 `insufficient`。这些状态是客户端标注，不传给检索或生成接口。分类中的版本题是静态历史问答，不是动态版本演进实验。

## 2. 来源与题目契约

每题保存问题、标准答案、必要事实清单、禁止推断、预期状态、来源分组、旧题重叠标识和证据组。组间要求全部覆盖，组内允许任一标注等价证据。每条证据绑定文档 ID、文档修订版、物理页或章节索引、原文摘录和可检索块 ID。

检验器逐条确认：

1. 文档修订版与登记表一致，位置类型与格式一致。
2. 摘录实际出现在指定原文位置。
3. 摘录存在于符合检索资格的块中，块 ID 与标注一致。
4. 题号不重复，题集恰好 50 题。

同页的其他段落不算命中。规范化仅处理兼容字符、空白和换行断词，沿用已有 PDF 判断规则。机器校验不证明摘录足以支撑全部标准答案；每题的语义审核仍为 `pending`，由独立评审复核。

问题中给出的数值与前提，例如“200 个点、1 s”，属于明确的测试输入，不是伪造的现场测量。缺证据题引用的是资料的已知边界，用于解释为何不能给出目标结论；不能据此称其拥有目标事实的正例证据。

## 3. 运行顺序

在项目根目录使用安装项目依赖的环境。工作区本地缺少 PDF 时，可用 `--pdf-root` 显式指向包含相同登记原文的工作区；登记表仍读取当前项目。以下命令只读取该 PDF 工作区。

```bash
conda activate accelerator-rag
export PYTHONPATH=src
python scripts/run_validity_pilot.py \
  --pdf-root /home/whloong/projects/accelerator-rag \
  --mode validate --output tmp/pilot-validation.json
python scripts/run_validity_pilot.py \
  --pdf-root /home/whloong/projects/accelerator-rag \
  --mode bm25 --output tmp/pilot-bm25.json
```

`bm25` 在 13 份 PDF 和 4 份 Markdown 的混合语料中逐题取前 20 个父块。主覆盖统计仅包含 45 道完整作答题；另外 5 题的边界证据覆盖单列。它不调用生成模型，不能得到回答正确率、拒答正确率或强混合检索成绩。

候选服务完成两路向量构建和版本检查后，运行：

```bash
python scripts/run_validity_pilot.py \
  --pdf-root /home/whloong/projects/accelerator-rag \
  --mode http --base-url http://127.0.0.1:18004 \
  --output tmp/pilot-hybrid-http.json
```

`18004` 是示例候选转发端口，必须对应已启动的候选服务。HTTP 入口先比对目录中的文档 ID、版本及原文可用性。缺少目标版本时停止，保存阻塞原因。它只发送 `{"query": "问题正文"}`，不会发送答案、摘录或评分清单，也不会追加旧 4 题。服务错误会保存已完成结果后停止，不自动跳过失败题或使用旧缓存补齐。

运行报告记录提交、工作区状态、语料修订版、检索结果或 HTTP 响应和耗时。当前工作区未提交，记录不等同于冻结实验。正式比较前另附候选配置、模型和索引契约、提示词及服务 trace；没有这些材料时不报告完整 token 成本或模型身份已验证。

### 3.1 修订题集

`scripts/build_validity_pilot.py` 是本轮题目的编写源。运行它会重新绑定证据，不是校验旧标注。文档变化后，先审阅问题、答案及摘录，再提升 `dataset_revision` 并生成新题集。已保存的旧结果继续指向旧题集，不能覆盖后还声称同一冻结实验。

```bash
python scripts/build_validity_pilot.py \
  --pdf-root /home/whloong/projects/accelerator-rag
```

## 4. 人工评分和失败归因

运行器输出同名 `.review.json` 空白审核表。每题至少核对答案正文、必要事实、禁止推断和引用原文，不能仅检查关键词或服务状态。

| 字段 | 判定方式 |
| --- | --- |
| `strict_correct` | 必要事实齐全，数值、比较符、单位、条件及版本均正确，未作禁止推断 |
| `condition_complete` | 该题要求的前提全部说明，适用范围不扩张 |
| `unsupported_claim` | 是否出现无依据的现场结论、唯一根因、参数或修复证明 |
| `citation_supported` | 每项事实能由对应版本的引文支持；仅链接可打开不算通过 |
| `failure_stage` | 资料、解析、召回、条件补全、版本选择、生成、评分歧义之一，可在备注解释多因 |

对部分回答题，说明可核实部分和缺失事实才算符合目标；整题拒答也可能遗漏已有信息。对完全缺证据题，提供相关背景不等于已回答所问目标事实。`status_matches` 只作接口诊断，语义正确性以人工评分为准。

标注两名评审和裁决记录前，不声称完成双人金标准。允许修改有歧义的问题，但必须记录修订，不在看到排名后暗中删掉未命中的证据。

## 5. 基线与下一阶段

先测已完成入库的现有混合系统，再与明确实现的最小原型比较。保持生成模型、候选预算、5 个父块和 6,000 个证据 token 等限制一致，同时报告调用次数。明确哪些条件是文档原文给出的，哪些是系统独立识别的。

当前 50 题按来源文档分组，旧题重叠单列。首轮展示逐题失败和分组结果，不用相近案例的多种问法扩大独立样本量。尤其是 10 道版本题不能代替 10 个变更事件。

后续动态实验另建事件清单，固定旧／新快照及受影响与不受影响的说明，覆盖变更前、变更后当前查询和历史回溯；同时检查过期遗漏和过度隔离。只有实际演练后才能报告维护成本优势。
